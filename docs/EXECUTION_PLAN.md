# FraudSpotter — Phased Execution Plan

Work one phase at a time. Do not implement the dashboard before the model and inference contract work.

## Phase 0 — Project scaffold (local)
- Verify Python 3.12 virtual environment, Git, `uv`, Ruff and Pytest.
- Verify dependencies and project structure generated by Antigravity.
- Add and read the canonical docs.
- Initialize Git only after checking `.gitignore` and confirming no datasets, weights or secrets are staged.

**Exit:** clean environment report, docs present, baseline tests pass, no secrets/large files staged.

## Phase 1 — Dataset acquisition and audit (Colab)
- Clone GitHub source.
- Download WELFake directly in Colab.
- Record provenance, checksum, schema, labels, nulls and class counts.
- Generate EDA and inspect source patterns.

**Exit:** verified source file, audit report, no assumed counts substituted for actual counts.

## Phase 2 — Cleaning, deduplication and splits (Colab)
- Implement conservative normalization/source-marker rules.
- Exact and near-duplicate analysis.
- Stratified group-aware 80/10/10 partitions, seed 42.
- Freeze and hash split manifest.

**Exit:** no exact/group overlap; split counts and class ratios recorded.

## Phase 3 — Classical baselines (Colab)
- Majority sanity baseline.
- MultinomialNB.
- Word + character TF-IDF Logistic Regression.
- Optional calibrated LinearSVC.
- Validation tuning only; save full pipelines and probabilities.

**Exit:** baseline artifacts and validation metrics saved.

## Phase 4 — DistilBERT fine-tuning (Colab T4)
- Paired title/body WordPiece tokenizer.
- 128/256/384 length experiments and headline-only ablation.
- Initial configuration from MASTER_SPEC.
- FP16, dynamic padding, accumulation, clipping, early stopping.
- Save recoverable checkpoints to Drive.

**Exit:** reproducible best checkpoint and training logs.

## Phase 5 — Selection and calibration (Colab)
- Compare validation metrics and efficiency.
- Select one primary model/sequence length.
- Tune balanced and optional conservative thresholds.
- Fit temperature scaling.
- Freeze configuration.

**Exit:** frozen `inference_config.json`.

## Phase 6 — Final evaluation (Colab)
- Run one final evaluation on the untouched test partition.
- Metrics, confusion matrices, bootstrap CIs and McNemar.
- Save probabilities/predictions and machine-readable reports.

**Exit:** complete WELFake results with no test-driven tuning.

## Phase 7 — Explainability (Colab, local smoke tests)
- Captum Integrated Gradients and token alignment.
- LIME wrapper and local explanation.
- Logistic Regression coefficients.
- Top-k vs random deletion and sufficiency experiments.

**Exit:** working explanations and quantitative faithfulness report.

## Phase 8 — Robustness and external diagnostics (Colab)
- Meaning-preserving transformations and information ablations.
- ISOT external evaluation and overlap audit.
- LIAR mapping and separate evaluation.
- Review at least 50 errors and categorize.

**Exit:** robustness, external, and error-analysis reports.

## Phase 9 — Backend (local)
- Implement ModelRegistry and common prediction interface.
- FastAPI `/health`, `/predict`, `/explain`, `/batch_predict`, `/metrics`, `/models`.
- Pydantic validation and clear error behavior.

**Exit:** API tests pass with real exported artifacts or explicit test fixtures.

## Phase 10 — Frontend (local)
- Streamlit overview, analyzer, explainability, model lab, robustness lab, batch analyzer, about/limitations.
- Call FastAPI; do not duplicate model logic.

**Exit:** single and batch flows work end-to-end.

## Phase 11 — Export and optimization
- PyTorch vs ONNX FP32 parity.
- Dynamic INT8 quantization.
- Compare outputs, test quality degradation and benchmark.
- Retain INT8 only if measured value is positive.

**Exit:** export/parity report and measured performance table.

## Phase 12 — Verification and packaging
- Pytest, Ruff, API integration, clean startup, Docker and CI.
- Verify model loading from documented artifact location.

**Exit:** tests pass and clean setup instructions work.

## Phase 13 — Academic submission
- README, architecture diagram, data/model cards, report, result figures, slides and viva notes.

**Exit:** every reported result is reproducible and clearly labelled as measured or target.
